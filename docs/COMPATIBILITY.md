# 既存KomgaToolとの比較と回帰防止

**2026-10-18の現行比較は [機能対応表](FEATURE_PARITY.md) を参照。以下は各比較時点の記録。**

2026-10-15、0.1.0.dev7で整理・変換・メタデータを比較し、dev8で完結情報、rc1で巻著者の反映を追加した。
既存KomgaToolで対応済みの入力や失敗条件を、公開版の仕様と回帰テストへ引き継ぐ。
運用環境、秘密情報、作品別の補正表、Git履歴は取り込まない。

比較対象は `normalize_cbz.py`、`fix_cbz_order.py`、`move_completed.py`、
`komga_writeback.py`、著者処理、作品照合、出版社・レーベル判定。
既存側のソースと関連テストを読み、既存スクリプトの実行や変更は行っていない。
外部情報の取得、通知、ポータルの各情報連携などの移植完了を示すものではない。

## ポータルと日常の導線の再比較（2026-10-17）

前の比較は書庫処理・補完の機能単位が中心で、ポータルと管理を含む日常の使い方の比較が不足していた。
今回、既存側のトップと管理画面の実際のGET応答、対応テンプレート、ポータルのデータ供給、管理の実行ルートを読み直した。
既存側の実行・更新ボタンは押さず、運用コード・設定・状態・蔵書を公開版へコピーしていない。

| 観点 | 既存KomgaTool | 公開版の対応・残る差分 |
| --- | --- | --- |
| 起動時の入口 | 読む作品を探すポータル。蔵書・Komgaへの導線がある | 取り込み整理へ置き換えた変更を取り消し、ポータルをトップへ復元。蔵書検索・一覧・完結作品を表示 |
| 取り込み整理（既存のノーマライズ）の位置 | 管理のメンテナンスから新規追加分をDry-Run / Execute | 管理の先頭と、ポータルの「追加した漫画を整理」から差分確認へ。実装の優先度とトップの役割を分ける |
| 最近追加した漫画 | 未完作品の追加日時順に、作品ごとの最新巻を表示 | 未実装。現在は蔵書の一覧を表示し、最近追加した順とは呼ばない |
| 完結一気読み | 完結作品を抽選し、作品情報やKomgaへ進む | 完結作品の一覧への導線を復元。抽選・作品情報ダイアログ・Komgaの作品IDによる直接リンクは未実装 |
| 今期アニメ・新刊・発見 | 所持する原作、新刊待ち、記事・ランキングなどをトップに集約 | 未実装。ポータルを維持したまま後続で情報源を追加する。未実装のカードや数値を表示しない |
| トップの負荷 | 入口を先に表示し、収集済みの情報を後で読み込む | 入口を先に表示し、蔵書の集計と少量のカードを後で取得。取り込み整理や補完を自動実行しない |
| 取り込み後の流れ | 既存のノーマライズからスキャン→補完→読み→タグへ連動 | 公開版では個別の確認付き操作。自動連動は未実装のまま残る |

取り込み整理の優先実装だけで、既存KomgaToolと同じ使用感や全機能が揃ったとは扱わない。

再レビューで、全角英字名の端のxが欠ける、楽天候補の括弧付き副題が消える、残留ファイルの記録が100件で切れる問題を修正した。
英字名・不明な副題を保持し、残留一覧は全件を保存する。補正仕様が古い検索キャッシュからの再採用も拒否する。
架空データの回帰テストと専用Komga 1.29.0 / 1.29.1で再確認し、詳細を [検証記録](VALIDATION.md) に記載した。

## 今回確認した差分

| 項目 | 見つかった差分 | 公開版の対応 |
| --- | --- | --- |
| ファイル名の巻数 | `_01` 以外にも、`作品1`、`作品（ 02 ） - 著者`、日本語直後の `v02` が不足 | 既知のフォルダ作品名を除いた末尾を読む。整数・小数・全角数字に対応 |
| 作品名中の数字 | 作品名中の括弧や `第3巻` を巻数として拾う場合がある | 既知の作品名を先に除去。括弧形式は末尾に限定 |
| ComicInfo.xml | ZIP/CBZのルートだけを読んでいた | サブフォルダ、RAR/CBR/7z、XML名前空間にも対応。画像を展開せずメタデータだけ読む |
| EPUBの巻数 | ファイル名しか読んでいなかった | container.xmlからOPFを特定し、`group-position` を優先。EPUB内部は変更しない |
| 巻数の食い違い | 書庫内の値による上書きが警告に出ない | ファイル名と書庫内の巻数を警告へ表示。不正な書庫内巻数も警告する |
| 日本語ZIP | UTF-8指定のないCP932名が文字化けする | ZIPの読み取りを共通化し、CP932で復元可能な名前を補正。補助ファイル名も保持 |
| 一時ファイル | 隠しCBZやAppleDoubleを蔵書として拾う | 隠しファイル、`__MACOSX`、リンク、通常ファイルでない対象をスキャンから除外 |
| ページ順 | 既存は辞書順 | Webの取り込み整理は同じ辞書順。別保存先へ生成するCLIの既定は自然順で、`--page-order lexicographic-path` も指定可能。順序を計画へ保存する |
| 整理・復元 | 実装方式が異なる | 上書き拒否・バックアップ・ローカル編集・中断からの復元を既存の回帰テストで維持 |
| Komga情報 | 既存はAPIで既読等を書き戻し、公開版は内容一致による復元を検証 | 複数ユーザーの既読・最新ページ・ロックを専用Komgaで検証。対応バージョン等の条件は維持 |
| タグ・ロック | 既存はタグをマージし、既存の分類を保持 | 公開版も追加が既定。ロック変更と一覧置き換えは明示的な指定を要求 |
| 完結時のKomgaタグ・status変更 | 既存は完結移動時に情報を書き戻す | dev8で専用CLIへ対応。分類・休載/打ち切り・ロックを保持し、値とロックを確認して反映・復元 |
| 複数著者・役割 | 既存の汎用処理は区切り・所属表記・「他」等に対処 | rc1で候補生成と巻単位CLIへ対応。中点・空白・Alex内のxを分割せず、名前/役割を確認して追加・復元 |
| 蔵書表示の負荷 | 既存Webは収集済みJSONとページ分割を使う。公開版は30秒後の全書庫再読み取りと全作品描画で大きく遅延 | 書庫メタデータを永続化し、属性が変わった書庫だけ再解析。Webの確認をバックグラウンド化、60作品ずつ表示。強制再読み取り・実行前検査は維持 |

ファイル名だけでは判断しにくい数字は自動採番しない。例えば、作品フォルダが `作品86` なら
`作品86_01.zip` を1巻と判定できるが、作品名の裏付けがない同じ名前からは推定しない。
作品名が一致しないファイルでは従来どおり明示的な巻表記と `_NN` / `_NNN` の限られた末尾形式を使う。

同名のComicInfo.xmlが複数ある、EPUBの巻数候補が食い違う場合、先頭の候補を無条件に採用しない。
読み取り警告を出し、利用可能ならファイル名の巻数へ戻す。整理プレビューで確認する。
書庫内項目数・中央ディレクトリ・メタデータの読み取り量を制限し、XMLのDTD・実体参照は拒否する。

ページ順は入力によって正解が異なる。`page1`、`page2`、`page10` は自然順、
`page1`、`page10`、`page2` は辞書順になる。計画の対応表で選ぶ。
ComicInfoのページ参照の元の並びは自動判定・書き換えせず、選んだ並びに合うことを利用者が確認する。

## 再比較で見つかった後退と修正（2026-10-16）

0.1.0rc1の後、既存KomgaToolの各スクリプトと共通処理をもう一度読み、初回範囲内で劣っていた動作を修正した。
件数は運用中のフォルダ名を形式ごとに数えただけで、作品名・著者名は取り込んでいない。

| 項目 | 見つかった差分 | 修正と検証 |
| --- | --- | --- |
| Komgaのバージョン | 書き込みを1.29.0の完全一致に限定。運用中の1.29.1で全書き込みが止まる | 1.29.1を追加。1.29.0との差分はWeb画面とバージョン表記のみ。専用の1.29.0 / 1.29.1で実機テスト各7件成功 |
| 著者の `ｘ` 区切り | 空白付きの ` x ` だけを区切っていた。運用中の1,234作品中、空白なしの `x`/`ｘ` が日本語名に接する作品が104件（日本語名同士88件、英字名と日本語名18件、重複あり）、空白付きは0件 | 全角 `ｘ` と日本語名同士の `x` を区切る。英字名の `x` は保持。既存の分割と1,228件で一致し、人数の差は0件。残る3件は既存が `Max` 等の末尾を削っていたもの |
| 読みのない作品の行 | 漢字・英字の作品が警告なしで「その他」へ移る計画になった。既存は中止して行の指定を求めた | 五十音の行を使う整理先へ新たに移す場合は要確認。既に「その他」にある作品は変えない |
| 入れ子の作品 | 外伝などが「[著者未設定] 外伝」として親から切り離された | 親と同じ相対位置で一緒に移動・復元。親を選ぶと入れ子も計画に含める。実機で2ユーザーの既読を確認 |
| Komgaの補助画像 | 作品画像・巻画像が元のフォルダに残った | Komga 1.29の規則に合う画像を移動・改名。曖昧な対応・名前の重なりは中止。残るファイルを計画に記録。実機で移動後もKomgaが画像を認識 |
| 小数巻の命名 | `第1.5巻` となり、ファイル名順で9巻と10巻の間に並んだ | 既存と同じ `第01.5巻`。桁数指定は整数部だけに適用 |
| AniListのタグ | 英語のまま。成人向け・関連度の低いタグも候補になった | 同梱の対訳表で日本語化。成人向け・Sexual Content・Hentai・関連度60未満を除外。読者層をジャンルへ。公開APIへの1件の検索で確認 |
| 楽天Booksの候補 | 作品名・読みに巻数が残り、あらすじ・読者層を取得しなかった。判型の指定で漫画文庫が漏れた | 漫画ジャンルで検索。巻数とレーベル注記を除き、販促行を除いたあらすじと読者層を候補に追加。Koboは後続版 |
| `series.json` | KomgaのMylar形式を読めず警告になった | Mylar形式の作品名・出版社・あらすじを読み取る。状態は整理先を変えるため取り込まない |
| 一括反映（2026-10-17） | 作品ごと・項目ごとにKomgaのIDを手入力し、計画のたびに対象書庫を全部読み直し、Komgaの全書籍一覧を3回取得していた。既存は `--apply` で全作品を一度に処理 | `prepare-komga-batch` で全作品を1計画に。書庫は属性で照合し、一覧は計画時・実行前後に各1回。1,200作品・19,200冊の模擬環境で計画約8秒・実行13〜23秒。既定は空欄だけを埋める |
| 読みの取り込み（2026-10-17） | Komgaの並び順にある読みを取り込めず、読みのない作品が要確認になった | 「カナ 題名」形式を含む並び順から未設定の読みを一括で取り込み、1つの操作IDで取り消す |
| スキャン上限（2026-10-17） | 既定20,000に対し運用中の蔵書が19,281冊 | 既定を50,000にし、上限の90%で警告 |

初回の報告で「楽天Booksは漫画に絞り込んでいない」としたのは誤りで、判型（コミック）の指定で絞り込んでいた。
漫画文庫を含めるため、既存KomgaToolと同じジャンル指定へ変更した。

## 検証の維持

`tests/test_legacy_compatibility.py` に架空のファイル名、XML、ZIP/RAR/7z/EPUBを使う24件を追加した。
既存の実データ・ソース・認証情報へアクセスせずに再実行できる。
読み取り結果に加え、誤認防止、巻数衝突時の停止、元ファイルのSHA-256・更新日時、
移動と復元、両ページ順での生成と取り消し、CLIの順序指定を検証する。

既存側で修正済みの入力形式を追加するときは、この比較表と架空の回帰ケースを一緒に更新する。
単体テスト・実機テストの結果と検証範囲は [検証記録](VALIDATION.md) を参照する。
