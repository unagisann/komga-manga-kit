## 最優先: 追加 → 差分確認 → ノーマライズ

トップは、読む作品を探すポータルを維持する。機能としては、作品フォルダへ追加した漫画の差分確認から実行までを最優先で仕上げる。
上部は既存KomgaToolsに合わせた共通ヘッダーとし、ポータル・蔵書・発見・新刊・今期アニメ・ランキング・完結移動・表紙修正・管理と蔵書検索をまとめる。全ページ共通の2段目のメニューは置かない。ヘッダーとポータルの機能一覧は、利用者が表示と順番を選べる。管理は既存Toolsと同じくタブ（メンテナンス・環境設定・自動更新・処理履歴）に分け、ポータルにもノーマライズへの入口を置く。
以下はrc1後の未リリース変更。[ノーマライズガイド](NORMALIZATION.md) に手順と制約を記載する。

### 各開発版の到達点

第1段階（0.1.0.dev1）では、実行データをライブラリから分離し、編集と処理履歴を再起動後も保持する。
手動編集はこのツールの表示・検索・整理計画に反映し、漫画ファイルやKomgaは変更しない。

第2段階（0.1.0.dev2）では、明示的に有効にしたCLIから `prepare` → `execute` → `restore` を利用できる。
全対象のバックアップ、計画後の変更検出、衝突時の中止、途中停止からの復元、ローカル編集の移動を実装。
隔離したKomga 1.29.0で、命名・完結フォルダへの移動・バックアップ復元と複数ユーザーの既読情報を検証した。
作品単位・同一ファイルシステムに限定し、書庫変換・外部補完・完結判定の自動化は次の段階に残す。
Web画面と既定の設定は引き続きプレビュー専用。[整理実行ガイド](ORGANIZATION.md) に制約と復元手順を記載する。

第3段階（0.1.0.dev3）では、ZIP/CBZ・RAR/CBR・7zを別保存先へCBZとして生成する。
画像の内容とComicInfo.xmlを保持し、ページを自然順に並べて連番化する。計画の確認・バックアップ・生成物の取り消しをCLIへ統合。
Komgaの別テストライブラリで生成物を解析し、元書庫・元の既読情報を保持することを確認する。
内容ハッシュが変わる変換先への既読移行と元書庫の置き換えは未実装。[CBZ生成ガイド](CONVERSION.md) に範囲を記載する。

0.1.0.dev4では、第3段階の移動・復元・CBZ生成の保存確定を補強する。
バックアップと移動先の内容・名前・新しい親フォルダを同期してから元の名前を削除し、操作記録の直前の版を保持する。
復元用の一時ファイルを記録し、強制終了後は対象を照合して取り消し・復元を再試行できる。
SQLiteの各接続でWALとFULL同期を使用する。実際の電源遮断・媒体故障は未検証。
[保存と中断からの復元](DURABILITY.md) に処理順序と保証の範囲を記載する。

第4段階（0.1.0.dev5）では、楽天Booksの書誌検索と、このツール内での項目別補完を追加する。
代表巻のISBNを選び、作品名・読み・著者・出版社の採用項目を確認・修正して保存する。
情報源・取得日時・調整した項目を保持し、誤った対応付けは変更・解除できる。整理・復元でも対応付けを引き継ぐ。
検索結果は1時間・ライブラリごとに100件まで保持し、連続通信と利用制限を制御する。
デモは架空データで利用できる。楽天の公式仕様と模擬応答で検証し、実APIへの認証接続は未検証。
[書誌検索・補完ガイド](METADATA_SOURCES.md) に設定・操作・対象範囲を記載する。

第5段階（0.1.0.dev6）では、AniListの漫画検索とタグ・ジャンルの補完を追加する。
作品の別表記・初出年・情報源を確認し、採用するジャンル・タグを調整して保存する。
楽天Booksの書誌情報とAniListの分類情報は別々に対応付け、個別に変更・解除できる。
手動編集とローカル書庫からの分類読み取り、蔵書検索、整理・復元での引き継ぎにも対応する。
既定では無効、デモでは架空データを使用する。通信間隔・429待機・1時間のキャッシュを共有し、
ネタバレ指定・判定不明のタグを除外する。公開APIの架空検索で疎通を確認し、実作品の照合は未検証。
補完情報のKomgaへの反映と自動照合は今後の対象とする。

第6段階（0.1.0.dev7）では、選んだ作品情報をCLIからKomga 1.29.0へ反映・復元する。
作品名・読み（並び順）・出版社・あらすじ・ジャンル・タグを対象に、変更前後の値とロックを確認する。
タグ・ジャンルは既存の値へ追加し、一覧の置き換え・ロック済みの値の変更は明示的に指定する。
計画後の変更や復元時の衝突を検出し、中断・通信結果不明時も操作記録と現在の値を照合する。
隔離したKomgaで6項目の反映・復元、書庫・書籍ID・複数ユーザーの既読情報の保持を検証する。
Web画面の保存はローカルの作品情報だけを変更する。[Komga反映ガイド](KOMGA_METADATA.md) に手順と制約を記載する。

第7段階（0.1.0.dev8）では、手動で完結にした作品のKomgaタグ・連載状態をCLIから反映・復元する。
既存KomgaToolの分類タグの保持・完結タグの重複防止・休載/打ち切り状態の保持を引き継ぐ。
連載中タグと完結タグを指定でき、値とロックの差分を計画へ保存する。ロック済みの変更は明示指定を要求する。
既存の操作記録・衝突検出・通信結果不明時の復元を共用し、移動後の同期と逆順の復元、最新既読位置を専用Komgaで検証する。
移動・Web保存への自動連動と完結の自動判定は未実装。[完結情報ガイド](COMPLETION.md) に手順を記載する。
