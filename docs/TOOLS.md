# 既存Tools相当の操作と設定

現在の機能対応は [機能対応表](FEATURE_PARITY.md) を参照。
ポータルを残し、発見・新刊・今期アニメ・ランキング・書籍移動・表紙修正と管理への入口、蔵書検索を上部の共通ヘッダーにまとめる。全ページ共通の2段目のメニューは置かない。
ヘッダーとポータルの機能一覧は「管理 → 環境設定 → 表示するメニュー」で、表示する項目と順番を変えられる。自動更新・取り込み整理・処理履歴・環境設定は既定で非表示。「管理」は環境設定へ戻れるよう常に表示する。

## 管理

既存Toolsと同じく、管理ページ内のタブで分ける。各ページには1種類の役割だけを置く。

- メンテナンス `/manage`: 実行する処理だけを作業順に並べる。取り込み（取り込み整理）、作品情報（補完・手動修正・AI補助）、ファイル（表紙修正・書籍移動）、Komga（作品情報の反映・スマート本棚の同期）。各カードに前回の実行日時・失敗・処理中と、保存済みの結果から分かる残りの作業（未実行の取り込み整理の差分、情報が不足している作品、要確認の表紙）を表示する。表示のために蔵書のスキャンや外部への接続はしない。不足件数は最後のスキャン結果があるときだけ出す。書籍移動の対象数は計算が重いため出さない。
- 環境設定 `/settings`: 表示するメニュー、Komga、情報源、AI補助、新刊通知をWebで保存する。情報源（楽天Books・Kobo・MangaUpdates・AniList）と、ポータルの機能が使う話題の取得（今期アニメ・漫画の発見・次にくるマンガ大賞）は別の区画に分ける。オフの機能にだけ関係する項目（楽天のアプリ、AI補助の接続、通知先）は折りたたむ。広い画面では目次を左に固定し、読んでいる区画を示す。APIキーなどの認証情報は、それを使う区画（Komga・楽天のアプリ・AI補助・新刊通知）で入力し、環境変数で設定済み・保存済み・未設定を表示する。保存してもページを読み直さず、未保存の変更は保存バーと離脱時の確認で知らせる。設定ファイルで決める項目（保存先・状態フォルダ・実行の有効化）は値の表示と変更方法の案内だけ。整理ルールの試行もここから開く。旧 `/settings/tools` はここへ転送する。
- 自動更新 `/automation`: 実行時刻・ステップ・今すぐ実行・結果。
- 処理履歴 `/jobs`: 処理の進み具合・結果と操作履歴を見る。復元は各処理の詳細から行う。実行ボタンは置かない。
自動補完を基本にし、手動修正は管理に置く。機能を揃えた後で、必要性と配置を見直す。

### 保存・整理した内容をKomgaへ反映する

Komga接続時は、補完・手動修正・AI提案の保存後、書籍移動・取り込み整理の完了後に「Komgaにも反映しますか？」を表示する。
「作品情報」「巻の著者」「完結タグ・連載状態」のうち、その処理に含まれる情報を選び、対象を引き継いだ差分確認 → 確認した変更をKomgaへ反映、の順に進む。差分の取得は非同期で、表示するだけではKomgaに書き込まない。
補完・修正では実際に保存した作品が対象。書誌の対応付けだけで情報が変わらない場合には反映を促さない。移動・取り込み整理では移動後の作品IDを使う。移動も行う場合は先に移動を済ませ、その完了後から反映する。
既定は空欄の補完と一覧への追加。既存の値も修正するときは「反映設定」で選び、差分を確認する。実行有効化・管理者認証・ロック・衝突・復元の条件は従来と同じ。結果から元の処理へ戻って、残る種類の情報の反映を続けられる。

メンテナンスの「作品情報をまとめて反映」 `/komga-sync` は、全作品をまとめて確認・再同期するときの入口として残す。通常の保存後に全作品を選び直す必要はない。

### 処理待ちと二重実行

スキャン・取り込み整理・補完候補の取得・表紙判定・情報源の更新・AI生成・書籍移動・Komga反映・復元など、画面の重い処理は非同期で受け付け、ライブラリごとに受付順で1件ずつ実行する。スマート本棚とページ修正の差分作成も同じ待ち行列を使う。
同じ処理・対象・設定の要求が待機中または実行中なら、二重に登録せず同じ処理の詳細を返す。異なる対象や実行と復元は別の処理として順番を待つ。完了・失敗・中断後は新たに依頼できる。

受付後は画面を離れても続行する。「順番待ち」と前にある処理の件数、進捗・結果は「管理 → 処理履歴」から確認できる。待機・実行中の受付上限は合わせて20件。同じ処理への再送は満杯でも既存の記録を返す。
受付・重複判定・実行開始は状態DBで管理する。同じホストで同じ実行データとライブラリを使うアプリプロセス間でも共有する。CLI実行は従来の操作ロック・有効化・確認値を使う。
サーバー停止時の待機・実行中タスクは、次回起動時などに「中断」として残す。自動で再実行せず、書き込み途中なら記録を確認し、必要に応じて復元してから再実行する。

従来の同期プレビューAPIは互換性のため維持する。画面からの本棚・ページ修正プレビューは `POST /api/tools/shelves/preview/jobs` と `POST /api/tools/pages/<book_id>/preview/jobs` を使い、202応答のIDで進捗・結果を取得する。設定や確認済みのローカル編集の保存など、短い処理は即時に応答する。

## 読む・見つける

- ポータル: 最近追加した作品ごとの最新巻、完結作品の抽選、所持作品のアニメ・新刊・紹介記事。
- 蔵書 `/library`: 既存Toolsのライブラリ探索と同じ。読者層・状態・年代のチップ（件数は蔵書全体）、検索語、作者（複数作品のある人）・出版社（上位24社）、並び順で絞り込み、60件ずつ「もっと見る」で追加する。条件はURLに残る。
- 今期アニメ `/anime`: 既存Toolsと同じ表紙の一覧。当季と前季から継続中の作品を、原作・漫画版の別名でも蔵書と照合する。持ってる・漫画版あり・すべて・継続中のチップとタイトル検索で絞り込み、制作会社・話数・AniList・楽天の検索リンクを出す。季節が変わると更新を促す。
- 新刊 `/new_volumes`: 連載中の作品について紙・電子の最新巻と予約を確認。既存Toolsと同じく「新刊あり・予約受付中・最新まで持ってる・要確認・前回値・エラー」の表に分け、紙と電子の巻数差（電子先行）、直近14日の発売、書店の検索リンク、作品ごとの再チェックを出す。関連本・分冊版・不確かな発売日は確認用に残す。

- 発見 `/discovery`: ぶくまるの紹介作品を表紙で探す。今日のおすすめは蔵書3冊・未所持2冊を基本に、同じ作品の重複を避けて日本時間の日付で選ぶ。候補が少ない場合はある作品だけを表示する。テーマ／最近完結の特集を選び、所持状況と作品名・著者で絞り込める。所持判定は個別に修正でき、Komga接続時は「Komgaで読む」、未接続時は作品詳細へ進む。「記事と蔵書を更新」は蔵書を読み直してから紹介記事を更新する。既存キャッシュに特集名がない場合は「紹介された作品」にまとめ、更新後にテーマと完結特集へ分かれる。楽天Kobo・マンバ・ナタリーは既存の `?source=rakuten` / `manba` / `natalie` で利用できる。
- マンガ大賞 `/tsugimanga`: 既存Toolsと同じく、歴代一覧（年ごとの取得状況）と年・部門別ページ `/tsugimanga/<年>/<部門>` に分ける。順位のある作品とノミネートを分け、得票ポイント・エントリー数・総投票数・書店リンクを表示する。所持判定が誤っている作品は蔵書を検索して対応を保存する。

新刊の通常操作は「新刊をチェック」1つ。未チェック・作品情報や書誌対応の変更・前回失敗した作品に加え、前回から7日経過した作品や予約巻の発売日が来た作品を自動で再確認する。所持巻数だけが変わった場合は直近の取得結果で差分を更新する。
「未チェック」は新規追加だけでなく、初回実行時の既存作品など、新刊の取得結果がない作品も含むため、専用ボタンは置かない。直近の結果も使わず問い合わせ直す「全件を再チェック」は、折りたたんだ詳細設定に置く。

情報源の更新と蔵書情報の更新はボタンから行う。通常のページ表示で書誌検索やフィード更新は始めない。
紹介画像は各情報源の画像サーバーからブラウザーで読み込む。
Komga未接続の「最近追加」は、蔵書情報を更新して初めて確認した日時であり、過去の登録日時は推定しない。

### 発見ページを実際の記事・蔵書で使う

サンプルモード（`app.demo: true`）は、更新ボタンも架空の記事・蔵書を使う。
実際のぶくまるの記事を取得するには、設定ファイルでサンプルモードを解除し、蔵書・実行データを別の保存先にして再起動する。

```yaml
app:
  demo: false
library:
  root: /path/to/manga
data:
  root: /path/to/manga-kit-state
tools:
  discovery_enabled: true
```

`/discovery` の「記事と蔵書を更新」で、公開RSSの取得、作品名・著者による所持照合、特集・表紙の表示まで実行する。
ぶくまるの取得にAPIキーは不要。取得結果と手動で修正した所持判定は実行データへ保存する。
蔵書ファイルの変更や `execution.enabled` の有効化は必要ない。
Komga未接続でも記事・照合・ローカル表紙は使え、所持作品から作品詳細を開ける。
「Komgaで読む」を使う場合は「管理 → 環境設定」でKomga URLとAPIキーを設定して、もう一度「記事と蔵書を更新」を押す。

## 接続・情報源・認証情報

「管理 → 環境設定」の各区画で有効化する。既定はすべて無効。
初期値は設定ファイル、Webで変更した非秘密の設定はライブラリごとの実行データに保存する。
漫画・実行データ・設定の保存先は分ける。秘密情報をリポジトリへ保存しない。

```yaml
rakuten:
  enabled: false
  application_id_env: RAKUTEN_APPLICATION_ID
  access_key_env: RAKUTEN_ACCESS_KEY
  origin: ""
tools:
  kobo_enabled: false
  anime_enabled: false
  discovery_enabled: false
  rankings_enabled: false
  mangaupdates_enabled: false
  ai_enabled: false
  notify_enabled: false
  ai_provider: chat
  ai_url: ""
  ai_model: ""
  ai_key_env: MANGA_KIT_AI_KEY
  notify_url_env: MANGA_KIT_NOTIFY_URL
  public_komga_url: ""
  credentials_file: "" # Webで登録するときだけ、設定専用フォルダの絶対パスを指定
```

環境変数を優先する。Webで登録した値は `credentials_file` の0600ファイルへ保存し、内容を応答・履歴・DBへ戻さない。
保存先は漫画・実行データの外にする。未入力の項目は保持する。環境変数の設定はWebから変更せず、環境変数で設定済みの項目はWebの入力欄を閉じる。`KOMGA_URL` を設定した場合のKomga接続先も同じ。
「接続を確認」「利用できるモデルを確認」は、入力中で未保存の接続先・方式・APIキーで確かめ、保存はしない。保存後と同じく環境変数を優先する。入力値を使う確認は管理者のみで、保存時と同じ検証を通す。保存済みの値での接続確認は従来どおり。
楽天BooksとKoboは同じアプリID・アクセスキーを使うが、対応付けは別々に保持する。KoboのIDはISBNとして扱わない。
MangaUpdatesは書誌エンドポイントのみを使い、配信・取得元の検索は行わない。

読書状況の機能は削除した。以前の設定ファイル・Web設定に残る `reading_accounts` は読み飛ばす。

## 管理・補完・反映

- 追加した漫画を整理（取り込み整理） `/normalize`: 整理せずに使う書庫は、確認結果から「変更せずに整理済みとして登録」できる（取り消し可）。 ライブラリ（または全体）とサブパスを選び、「差分を確認」→「この内容で実行」。上限と再確認は詳細設定にまとめる。「差分確認後、そのまま実行」はWeb実行を有効にした場合だけ利用でき、要確認や上限到達では停止する。[操作と復元](NORMALIZATION.md) を参照。
- 補完 `/metadata`: 不足項目の候補、未登録の対応付け構築、全作品の対応付け再確認。最大60作品ずつ。
- 書籍移動 `/moves`: 整理ルールが決める場所と今の場所が違う作品を、状態・検索で絞って選び、移動先と衝突を確認してから実行・復元する。完結した作品の移動もここで行う。読みが未設定などで場所を決められない作品は理由を表示して選べない。旧 `/completion` は転送する。
- 表紙修正 `/pages`: 既存Toolsと同じく、判定の区分（1枚目白黒・2枚目カラー、1枚目が白黒、破損・画像なし）、状態（未対応・完了・スキップ）、検索で絞り、1枚目のプレビューから1冊ずつ修正する。［表紙を調べる］は1枚目と2枚目を1/8の大きさで読み込み、色の鮮やかさ（Hasler・Süsstrunkのcolourfulness）で判定する。1枚目が6未満なら白黒、そのうえで2枚目が15以上なら入れ替え候補とする。淡い色や暗い色の表紙はカラーとして扱い、ほぼ色を使わずに描かれた表紙は白黒に含まれることがある。黄ばんだ紙の白黒スキャンは色として扱われる場合がある。結果は判定方法の版とともに巻ごとに保存し、サイズか更新日時が変わった巻だけを調べ直す（判定方法が変わったときは全巻）。修正画面ではページのカードを並べ替え・削除指定し、「変更内容を確認」で差分を確かめてから実行する。
- 作品詳細 `/shelf/series/<id>`: Komga未接続でも作品を開けるkit独自の画面。あらすじ・書誌、所持巻の表紙、レーベル・読者層・連載開始年・評価の編集。
- Komga反映 `/komga-sync`: 作品情報・読み・タグ、巻の著者、完結タグ・連載状態。既定は空欄の補完と一覧への追加。
- スマート本棚 `/smart-shelves`: 変更を確認して同期。Manga Kitが作成したIDだけを更新し、個人の同名本棚があれば停止する。取得元が未更新なら保持。
- AI補助 `/ai`: 設定したモデルで提案を取得し、根拠・差分を確認して保存。項目を編集・選択でき、保存前へ戻せる。別の作品と同じあらすじ、日本語以外、HTML、後の巻の記述も点検する。

AIには作品名・著者・出版社・現在のあらすじ・対応付けの出典を送り、漫画本文やローカルパスは送らない。
Chat Completions互換は対応するAPIのベースURL、Geminiは `https://generativelanguage.googleapis.com/v1beta` を指定する。
モデルは保存した接続先から一覧を取得できる。GeminiのWeb検索は提案取得時に個別に選ぶ。
根拠がない・著者や作品が異なる提案を自動で確定しない。ローカルで保存した後のKomga反映は別の確認操作。

書き込みは `execution.enabled: true` と `execution.web_enabled: true` が必要。
ローカル接続、または `MANGA_KIT_ADMIN_TOKEN` の管理者認証を使い、表示した差分を確認して実行する。
既定のプレビュー、ロック済み項目の保護、衝突時の停止、履歴からの復元を維持する。

## 表紙とページ

`/pages` で巻を選び、残すページ・順序・先頭の表紙を指定して確認する。
削除・並べ替え時はComicInfo.xmlのページ数・ページ参照・表紙参照を更新する。画像のバイト列は再圧縮しない。
元書庫はバックアップし、`/pages/trash` から操作を確認・復元できる。
バックアップの完全削除は別の操作で、現在の書庫は消さない。完全削除後はその操作を復元できない。

Komga 1.29.1では同じページ数の表紙・順序変更まで対応する。
ページ数が変わる削除は、全ユーザーの読了日を保持しながら位置を再対応させるAPIがないため停止する。
Komgaで管理している漫画の接続設定を外して制約を回避しない。

## 自動更新と取り込み後処理

`/automation` で時刻（日本時間）とステップを保存する。アプリ起動中の日次実行と今すぐ実行に使う。
取り込み整理の後に続けて行う処理（Komgaスキャン・書誌・タグの候補）は取り込み整理の画面で選び、今回整理した作品だけに実行する。実行の記録と再開はこの画面で共通に扱う。「自動反映する」は両方に適用する。
ホストの既存systemdタイマーや既存Toolsは操作しない。
既定は候補と計画の作成まで。自動反映には実行設定と「自動反映する」の両方を有効にする。
失敗したステップは結果を残し、完了したステップを繰り返さず再開する。
途中でKomga反映が止まった場合は、記録した操作リンクから確認・復元してから再開する。

通知は `notify_enabled` を明示的に有効にし、環境変数のHTTPS Webhookへ `{content: 新刊案内}` をPOSTする。
同じ作品・最新巻の送信成功を記録し、再通知を抑える。送信失敗は新刊の取得結果と分けて表示する。

## 1冊だけCBZにする

Windowsを含む単体変換用の経路。書き込みを有効にしていなくても最初の確認はできる。
ZIP/CBZは標準ライブラリ、RAR/7zは別途libarchiveが必要。Windows実機での検証は未実施。

```console
manga-kit --config /path/to/settings.yaml convert-one source.zip --output converted.cbz
manga-kit --config /path/to/settings.yaml convert-one source.zip --output converted.cbz --confirm 表示したdigest
```

2回目の生成には設定ファイルで `execution.enabled: true` が必要。
元書庫を保持し、存在しない別名のCBZへ出力する。出力先のフォルダを事前に作る。
出力を途中の状態で公開しないため、同じ保存先内のハードリンクに対応したファイルシステムを使う。
