# リリースノート

## 現状を整理済みとして登録・蔵書の読み直しの移動（2026-10-21、未リリース）

取り込み整理の確認結果から、変更予定・要確認の書庫を、書庫を変更せずに整理済みとして登録できるようにした。整理ルールの外で追加した漫画を、そのまま使う場合に使う。次の確認からは、書庫・作品情報・整理ルールが変わるまで差分に出ない。登録した確認結果からは実行できず、処理履歴に残り、結果画面から取り消せる。書庫を変更しないため、Web実行の有効化は不要（管理者のみ）。
メンテナンスの「蔵書を再スキャン」は取り込み整理とは関係がなく、画面を開いている間は自動で読み直すため、カードを外した。すぐ反映したいときは「ライブラリ探索」の「読み直す」を使う。

## 取り込み整理の後に続けて行う処理（2026-10-21、未リリース）

「追加した漫画を整理」の画面で、整理の後に続けて行う処理（Komgaでスキャン・書誌・読み・著者の候補・タグ・ジャンルの候補）を選べるようにした。「差分確認後、そのまま実行」とは別の設定で、選んだ内容は次回も表示する。使えない項目は理由を添えて選べなくする。
対象は今回整理した作品だけにした。以前は自動更新の設定に従い、毎日のステップを蔵書全体へ実行していた。候補は「補完・個別確認」で確かめてから保存し、自動反映は従来どおり自動更新の「自動反映する」と実行設定が必要。
整理の結果画面に進み具合と候補への入口を表示し、「Komgaにも反映しますか？」は続けて行う処理が終わってから案内する。自動更新の「取り込み整理の完了後にも実行する」は廃止し、該当するステップを引き継ぐ。

## 新刊チェックの操作を整理（2026-10-20、未リリース）

通常の操作を「新刊をチェック」1つにした。通常チェックに含まれる「未チェックの作品だけ」のボタンを削除し、「全件を再チェック」は詳細設定へ移した。未確認・情報変更・失敗・更新時期に応じて対象を選ぶ既存の処理は維持する。

## 「ノーマライズ」の表示名を変更（2026-10-20、未リリース）

分かりにくかった「ノーマライズ」を、画面名・ボタン・メンテナンスのカードでは「追加した漫画を整理」、処理履歴・メッセージ・ヘッダーのメニューでは「取り込み整理」と表示する。URL（`/normalize`）・CLI・設定項目・コード上の名前は変えない。既存KomgaToolsと比べる文書では、相手側の機能名として「ノーマライズ」を残す。

## 設定の整理とメンテナンスの状況表示（2026-10-20、未リリース）

環境設定で、情報源（楽天Books・Kobo・MangaUpdates・AniList）と、ポータルの機能が使う「話題の取得」（今期アニメ・漫画の発見・次にくるマンガ大賞）を分けた。各スイッチに用途を添えて一覧にし、オフの機能にだけ関係する楽天のアプリ・AI補助の接続・通知先は折りたたむ。広い画面では目次を左に固定し、アイコンと縦線で項目を示して、開いた直後から読んでいる区画を強調する。目次からの移動先は、折り返したヘッダーの高さに合わせる。
メンテナンスの各カードに、前回の実行日時・失敗・処理中と、未実行の取り込み整理の差分・情報が不足している作品・要確認の表紙の件数を表示する。保存済みの結果だけを読み、ページを開いても蔵書のスキャンや外部への接続はしない。

## 環境設定の認証情報と保存（2026-10-20、未リリース）

APIキー・楽天のアプリID・アクセスキー・通知先URLを、別区画の「認証情報」から、それを使うKomga・楽天のアプリ・AI補助・新刊通知の区画へ移し、環境変数で設定済み・保存済み・未設定を表示する。環境変数で設定済みの項目と `KOMGA_URL` 指定時の接続先は、Webの値が使われないため入力欄を閉じる。設定と入力した認証情報は1回の保存でまとめて保存し、設定が検証で拒否されたときは認証情報も書き込まない。
「接続を確認」「利用できるモデルを確認」は、入力中の値で確かめる。保存時のページ再読み込みをやめ、メニューと他の区画の未保存の入力を失わない。メニューの保存はその場でヘッダーへ反映する。未保存の変更は保存バーに表示し、「元に戻す」で保存済みの値へ戻せる。ページを離れる前に確認する。

## 保存・整理からKomga反映への導線（2026-10-20、未リリース）

補完・手動修正・AI提案の保存、書籍移動・取り込み整理の完了後に「Komgaにも反映しますか？」を表示する。保存・整理した作品を引き継いで非同期に差分を確認し、確認後に反映・復元する。移動後は新しい作品IDを使い、全作品へ対象を広げない。全作品の反映画面はまとめて確認・再同期する入口として残す。CLIだけで反映するとしていた古い画面の説明も更新した。

## 非同期タスクの重複防止（2026-10-19、未リリース）

同じ処理の連打や別タブからの送信は、待機・実行中のタスクへまとめる。異なる処理はライブラリごとに受付順で1件ずつ実行し、同じ状態DBのローカルプロセス間でも受付と実行順序を共有する。画面と処理履歴に順番待ち・待機件数・詳細へのリンクを表示する。
スマート本棚とページ修正の差分作成も画面からは非同期で受け付ける。画面を離れても処理履歴から結果へ戻れる。サーバー停止後のタスクは自動再送せず中断記録を残す。操作手順は [Toolsガイド](TOOLS.md#処理待ちと二重実行)、確認結果は [検証記録](VALIDATION.md) を参照。

## 既存Toolsの機能追加（2026-10-18、未リリース）

表紙修正を既存Toolsと同じ画面にし、全書庫の表紙判定（1枚目が白黒、1枚目白黒・2枚目カラーの入れ替え候補、破損・画像なし）を追加。判定と縮小プレビューのため Pillow を依存に加えた。完結移動は整理ルールどおりの場所へ移す「書籍移動」に改め、作品詳細の見た目を揃え、読書状況の機能を削除した。

新刊・今期アニメ・ランキングを既存Toolsと同じ構成へ変更。新刊は状態別の表、今期アニメは表紙と所持・漫画版・継続の絞り込み、ランキングは歴代一覧と年・部門別ページ（順位とノミネート、得票ポイント）にした。

管理を既存Toolsと同じタブ（メンテナンス・環境設定・自動更新）に処理履歴を加えて整理し、2つの設定ページを環境設定へ統合。ヘッダーとポータルの機能一覧は、表示する項目と順番を環境設定で選べるようにした。旧 `/settings/tools` は環境設定へ転送する。

ノーマライズを「対象設定 → 差分を確認 → この内容で実行」へ整理。ライブラリ・全体・サブパスと、折りたたむ上限／再確認を追加。既定オフの「差分確認後、そのまま実行」は内部の検証を保ち、要確認時には停止する。限定対象の実行でも、対象外との衝突確認・既存の復元・Komga既読情報の検証を維持した。

発見ページを既存Toolsと同じ構成へ変更。日替わりのおすすめ、テーマ別と最近完結の特集を表紙で並べ、特集切り替え・所持状況と作品名／著者の絞り込み・Komgaと紹介記事へのリンクを追加。「記事と蔵書を更新」で両方を明示更新する。古い紹介キャッシュと所持判定の修正は引き続き利用できる。

機能メニューを既存KomgaToolsに合わせて最上部の共通ヘッダーへ統合し、本文上のポータル・管理サブメニューを撤去。蔵書検索・整理への入口・テーマ切り替えもヘッダーへまとめた。

ポータルは既存KomgaToolsと同じ構成（統計と今期のピック、機能への入口、最近追加・今期アニメ・完結一気読みの棚、新刊の一覧、今日のおすすめ）に戻した。背表紙の本棚 `/shelf` は削除し、作品詳細 `/shelf/series/<id>` はURLを維持した。

ポータルを維持し、Kobo・MangaUpdates・新刊・発見・今期アニメ・ランキング・スマート本棚・読書状況、AI補助、表紙/ページ修正・ゴミ箱、完結移動/Komga反映、設定・自動更新・取り込み後処理・PWA・単体変換を追加。Komga 1.29.1で書庫再生成と既読情報・復元を検証した。機能・制約・未検証範囲は [機能対応表](FEATURE_PARITY.md)、操作は [Toolsガイド](TOOLS.md)。配布物はまだ再生成していない。

## 既存KomgaToolとの再比較による修正（rc1以降・未リリース）

既存KomgaToolより劣っていた初回範囲内の動作を修正した。詳細は [互換性の比較](COMPATIBILITY.md)。

- Komga 1.29.1への書き込みに対応。1.29.0からの差分はWeb画面だけで、専用の1.29.1でも実機テスト一式が成功。
- 著者候補: 全角 `ｘ` と、日本語の名前同士をつなぐ半角 `x` を区切りとして扱う。`Alex` などの英字名は分割しない。
- 整理: 五十音の行を使う整理先で読みがない漢字・英字の作品を、「その他」へ移さず要確認にする。
- 整理: 外伝などの入れ子の作品を、親と同じ相対位置のまま一緒に移す。親を選ぶと入れ子も計画に含める。
- 整理: Komgaの作品画像（cover等）と巻の画像を一緒に移動・改名する。残るファイルを計画に記録する。
- 命名: 桁数指定を整数部へ適用し、1.5巻を `第01.5巻` とする（既存KomgaToolと同じ）。
- AniList: 同梱の対訳表で日本語化。成人向け・関連度60未満のタグを除外し、読者層をジャンルに含める。
- 楽天Books: 漫画文庫を含む漫画ジャンルで検索。巻数を除いた作品名・読み、販促行を除いたあらすじ、読者層を候補にする。
- KomgaのMylar形式の `series.json` を読み取る（状態は取り込まない）。

### 運用規模の手間の修正（2026-10-17）

- `prepare-komga-batch --mode metadata|completion|authors`: 複数作品・全作品を1計画にし、作品ごとに送信予定を記録して反映、逆順に復元。
- 一括反映は書庫の内容を読まず、サイズ・日時の属性とKomgaのパス・巻構成・サイズ・ハッシュ・IDで照合する。Komgaの一覧は計画時・実行前後に各1回。
- 一括の作品情報は既定でKomgaの空欄だけを埋める（`--overwrite` で置き換え）。ローカルの空欄でKomgaの値を消さない。
- `prepare-reading-import`: Komgaの並び順（「カナ 題名」形式を含む）から未設定の読みを一括で取り込み、1つの操作IDで取り消す。
- 1作品の `prepare-metadata` / `prepare-completion` / `prepare-authors` で `--komga-series` を省略できる。書籍一覧の取得を1回に減らした。
- スキャン上限の既定値を20,000から50,000にし、上限の90%で警告する。

### この修正での動作の変化

- 小数巻を含む作品の整理プレビューで、`第1.5巻` が `第01.5巻` への改名として表示される。
- 読みのない漢字・英字の作品は、完結フォルダ等の五十音の行へ移す計画が要確認になる。既に「その他」にある作品はそのまま。
- 新しい検索結果のAniListタグ・ジャンルは日本語になる。保存済みの編集・Komgaの値は変更しない。
- DB形式は3のまま。補正仕様の変更前に作った検索結果は再利用・採用せず、再検索を求める。
- `library.max_files` を指定していない設定では上限が50,000になる。明示した値はそのまま使う。

### 再レビューでの追加修正

- 著者候補で全角英字名の先頭・末尾のxを失わないようにした。`Ａｌｅｘ`、`Ｍａｘ`、`Ｘａｖｉｅｒ` と混在表記を保持し、日本語名同士の `ｘ` 分割も維持する。
- 楽天Booksの「作品（続編）」等をレーベルと誤認して削らないようにした。不明な括弧は保持し、巻数に続くレーベル形式の注記・明確な版表記だけ除去する。
- 残留ファイルの記録を100件で打ち切らず、全件を計画に保存する。

## 実ライブラリ確認後の表示速度修正

約1.9万冊では、30秒のメモリキャッシュ切れのたびに書庫内を全件読み取り、画面表示を長時間待たせていた。
通常閲覧には書庫の属性に対応する永続メタデータキャッシュを追加し、変更された書庫だけを読み直す。
蔵書・メタデータ一覧は60作品ずつ表示し、明示的な再スキャン中も前回の結果を閲覧できる。
CLIの実行前や情報保存前の書庫再確認、移動・復元の安全条件は維持する。Komga同期や自動実行は追加していない。

蔵書整理は画面を開くたびの全冊計算をやめ、前回の確認結果と日時を表示する。
「配置を確認」で未変更の書庫を再利用しながら全冊を更新し、要確認を優先して20件ずつ表示する。
検索・状態の切り替え・ページ送りは保存済みの全件結果から行い、処理履歴でも同じ操作ができる。
整理ルールを折りたたみ、変更中のルールと前回結果の違いを明示する。

## 補完候補の照合改善（2026-10-17、未リリース）

- 作品名・確認済みの別名・著者一覧・出版社の照合理由を候補と差分画面に表示。同名別著者、短い作品名、副題・関連本、版違いを要確認にし、初期の採用チェックを外す。
- 楽天の出版社とレーベルを分け、通常/文庫/新装/特装などの明示的な版表記と判型を表示。ジャンルと矛盾しない明示的なレーベル表記からだけ読者層を提案。
- 確認して対応付けた作品名・AniListの別表記を次の検索と照合に使用。元の商品・版・レーベル・読者層の根拠・保存時の確認事項を情報源と履歴に保持。
- DBスキーマは3のまま。既存リンク・編集・操作記録は保持し、旧仕様の検索候補だけ再検索を求める。外部APIの実認証・実作品照合の検証範囲は変更しない。

## 操作の入口と自動補完（2026-10-17、未リリース）

- 上部をホーム・蔵書・自動補完・管理の4項目へ整理。蔵書整理・手動修正・処理履歴・設定・ロードマップを管理内へまとめた。既存URLを維持。
- 自動補完は不足項目のある作品をまとめて選択し、最大60作品の候補を取得する。照合できる候補の内容を確認して空欄だけを一括保存する。
- 曖昧な候補は個別確認、取得できない項目は管理の手動修正へ案内。保存済み情報とWebの整理プレビュー専用方針を保持。
- API制限を尊重して順番に取得し、429では残りの検索を中止。候補の期限切れや保存前の編集を検出すると全件の保存を中止し、DBでの一括確定と再送の二重適用防止を行う。

## 追加・変更分のノーマライズ（2026-10-17、未リリース）

- 普段の入口を「作品フォルダへ追加 → 差分確認 → ノーマライズ」に変更。上部をノーマライズ・蔵書・管理の3項目へ整理し、補完も管理へ移した。
- 明示的に有効化したWebで、名前・配置・CBZ化・辞書順のページ連番化を一つの操作として実行。既存の画像とComicInfo.xmlを保持し、全対象のバックアップと衝突を検出する復元を追加した。
- 追加・変更分の確認を保存し、確認後の変更を検出。確認済み書庫を再生成せず、20冊ずつ差分を確認できる。
- 原本削除直後のSIGKILLからの復元と、隔離Komga 1.29.1で内容を変えないZIP→CBZ命名・復元・複数ユーザーの既読情報を検証。Komga連携中の内容ハッシュが変わる再生成は未対応のため停止する。
- 設定と使い方は [ノーマライズガイド](NORMALIZATION.md) を参照。

## 更新時の注意

dev8からrc1のDB形式は3のまま。停止して設定・実行データ全体・ライブラリを一緒にバックアップしてから更新する。
通常の更新では絶対パス・名前付きボリューム・実ファイルを維持する。
物理的に作り直したライブラリでは旧操作は履歴として参照し、新しい計画を作る。
詳しい手順は [運用ガイド](OPERATIONS.md) を参照する。

## 制約と次の版

既定設定の整理はプレビュー専用。Webノーマライズは追加設定で有効化。Komga書き込みは1.29.0 / 1.29.1、著者反映は1計画50巻まで。
楽天BooksとAniListの実APIは試験対応・既定無効で、検証範囲を [対応環境](SUPPORT.md) に記載した。
AI読み、新刊確認、WebからのKomga作品情報反映、完結自動化、変換先への既読移行は後続のv0.1系で進める。
ダウンロードやダウンローダー連携は対象外。

正式公開時はrc1の成果物を改名せず、版番号を0.1.0へ変更し、テストと配布物の生成・確認を再実行する。
既存運用データや秘密情報を持ち込まず、成果物・チェックサム・リリースノートを揃えて公開する。
