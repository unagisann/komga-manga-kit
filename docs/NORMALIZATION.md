# 追加した漫画をノーマライズする

普段の操作は「作品フォルダへ漫画を追加 → 追加・変更分を確認 → 変更前後を確認して実行」です。
起動直後は読書の入口になるポータルです。「追加した漫画を整理」、または「管理 → ノーマライズ」から始めます。
補完・手動修正・整理ルール・履歴・設定も「管理」にあります。

## 最初の設定

既定ではプレビューのみです。漫画の保存先と実行データを別々に指定し、Web実行を有効にして再起動します。

```yaml
app:
  demo: false
library:
  root: /path/to/manga
data:
  root: /path/to/manga-kit-state
execution:
  enabled: true
  web_enabled: true
```

Linux/POSIXで利用します。漫画フォルダと実行データの両方に書き込み権限と空き容量が必要です。
Dockerの既定のライブラリマウントは読み取り専用なので、実行用に書き込み可能に変更してください。
ローカル以外から実行する場合は、環境変数 `MANGA_KIT_ADMIN_TOKEN` による管理者認証が必要です。
Dockerなど、アプリから見た接続元がループバックにならない構成でも管理者認証を設定します。

## 使い方

1. `library.root/連載中/[作者] 作品名/` など、作品ごとのフォルダへ漫画を追加します。
2. 「追加・変更分を確認」を押します。ファイルはまだ変更しません。確認処理中は画面を離れてもかまいません。
3. 変更前後のパス、CBZ再生成の有無、要確認の理由を確認します。表示は20冊ずつ、冊数は全件の合計です。
4. 確認欄にチェックし、「確認した内容でノーマライズを実行」を押します。
5. 完了後に再確認すると、確認済みの書庫は変更予定に出ません。追加した巻だけを次の対象にできます。

巻数不明、重複、壊れた書庫、ルート直下の書庫などは要確認になります。同じ作品に要確認がある場合は、その作品全体を実行対象から外します。
作品名・著者・読みなどの不足項目は「管理 → 作品情報の補完・個別確認」で補完し、取得できないものだけ手動修正します。
情報の補完をしていなくても、作品フォルダと巻数を判別できればノーマライズできます。
確認後にファイル・作品情報・ルールが変わった場合は実行せず、再確認を求めます。

## 何を変更するか

- 設定済みの整理ルールに従い、作品フォルダと巻ファイル名を整えます。
- ZIP/CBZ・RAR/CBR・7zをCBZに揃えます。RAR/7zにはlibarchiveが必要です。
- 既存KomgaToolと同じ辞書順（書庫内の相対パス順）でページを並べ、`0001.avif` などの連番に揃えます。画像形式は保持します。
- 画像を再エンコードせず、計画した全ページの内容と順序を検証します。既存のComicInfo.xmlと補助ファイルの内容を保持します。XMLのページ数・参照範囲を検証しますが、参照先の意味は推定しないため、選んだ順序に合うことを確認してください。
- すでに連番・格納順が揃ったZIPは、内容を再生成せずCBZへ名前を変えます。確認済みのCBZを毎回作り直しません。

EPUBは名前と配置だけを整え、内部の変更やCBZへの変換は行いません。
画像の内容から正しいページ順を推定する機能ではありません。辞書順が読書順と異なる書庫は、実行前に元のページ名を見直してください。

## バックアップと復元

変更前に対象ファイルを `data.root/operations/操作ID/backup/` へバックアップします。
CBZの生成と検証をすべて終えてから元書庫を置き換え、途中の状態を操作記録に保存します。
差分画面の「この操作を元に戻す」から、元の書庫・名前・日時・権限とローカルの編集情報を復元できます。
過去の差分画面は「管理 → 処理履歴 → 追加・変更分の確認 → 変更内容を確認・実行・復元」から開きます。
復元時に生成物や復元先が変更されていた場合は上書きしません。

CLIでもWebで確認した操作IDと確認値を使い、`execute` / `restore` を実行できます。
処理を強制終了した場合は、その操作の復元を行ってから再確認します。
実際の電源遮断・媒体故障の検証は行っていません。[保存と中断からの復元](DURABILITY.md) も参照してください。

## Komga連携中の処理

内容を変えない命名・移動はKomga 1.29.0 / 1.29.1、内容が変わる再生成は検証済みの1.29.1に対応する。
ハッシュ有効、自動スキャン・ゴミ箱自動削除・自動変換の停止、ルートと一致するパス対応等の条件は [整理実行ガイド](ORGANIZATION.md) と同じ。

1. 元のバイト列を保ったまま名前・配置を変更し、Komgaのハッシュ復元で既読情報を引き継ぐ。
2. 移動後の書籍ID・既読情報・ロック済み情報を記録し、同じパスでCBZを再生成する。
3. 再スキャン後に、書籍ID・新しいハッシュ・既読位置・読了日・ロック済み情報を照合する。
4. 復元時は同じパスで元の内容に戻して照合してから、元の名前・配置に戻す。各段階を操作記録へ保存する。

ZIP/CBZ・RARの再生成と、置き換え途中の失敗からの復元を、2ユーザーの専用Komgaで検証した。
読書位置は元の辞書順を前提とする。画像の内容から意味的なページ対応を推測しない。
ページ数が変わる削除は対象外で、表紙・ページ修正画面でもKomga連携時は停止する。
Komgaで管理している蔵書の接続設定を外して制約を回避しない。
