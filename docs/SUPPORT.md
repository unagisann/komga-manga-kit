Pythonの下限は3.11。3.12、3.14以降、Windows/macOS、x86_64、別のコンテナ基盤、上記を超える規模・ネットワークファイルシステムでの動作は今回の実機確認に含めない。
Komgaの他バージョンはWebの読み取り確認と、書き込み対応を分けて扱う。未知の書き込みバージョンでは中止する。
実際の電源遮断・媒体故障・分散ストレージの保存保証を検証したものではない。

## 実行範囲

初回の書庫内メタデータ読み取りは冊数・保存媒体によって数分かかる。成功した結果は保存し、通常閲覧では未変更の書庫を開き直さない。
Webの定期確認はバックグラウンドで行い、一覧は60作品ずつ表示する。明示的な再読み取り・CLIの実行前確認は書庫を読み直す。

- 既定設定の整理はプレビュー専用。Webの取り込み整理は `execution.web_enabled: true` を追加して明示的に有効化する。[手順と制約](NORMALIZATION.md) を参照。
- CLI実行には `execution.enabled: true` と `digest` の確認が必要。デモでは実行しない。
- 移動は作品単位・同一ファイルシステム。書庫とsidecarをバックアップし、衝突・後からの変更を上書きしない。
- 1作品の著者反映は1計画50巻まで。巻ごとの名前/役割とロックを復元する。
- 一括反映（`prepare-komga-batch`）は1計画5,000作品・50,000巻まで。書庫の内容は読まず、サイズ・日時とKomgaのパス・ハッシュ・IDで照合する。
  サイズと日時を保ったまま中身だけを差し替えた書庫は検出できない。既定はKomgaの空欄だけを埋める。
- Komga書き込みはパス・ID・内容ハッシュ・解析状態と、停止した自動スキャン等の条件が必要。
- 条件付きPATCHがないためKomgaの同時編集を禁止する運用が必要。同じ値にした第三者の変更とは区別できない。
- CLIのCBZ生成は別保存先へのコピー。Webの取り込み整理はバックアップ付きで元書庫を置き換える。Komga 1.29.1では移動後に同じパスで再生成し、書籍ID・既読位置・読了日を検証する。別ライブラリへの任意の既読移行は行わない。
- 読み・著者候補は確認用。巻数不明、曖昧な照合、版違いを無条件に自動確定しない。
- 復旧で物理的に作り直したライブラリには旧操作計画を再利用しない。編集・履歴は同じルートパスなら引き継げる。

RAR/7zにはシステムのlibarchiveが必要。EPUBは所在・巻数の読み取りと整理が対象で、CBZ変換は対象外。
POSIXのモード・更新日時・内容は検証しているが、ACL、拡張属性、所有者の移行を完全に保持する汎用バックアップツールではない。
Web反映・AI・新刊・自動更新などの追加内容と未検証範囲は [機能対応表](FEATURE_PARITY.md) を参照。初期設定ウィザードは未実装。

## 外部APIの確認範囲

楽天Booksは公式仕様・模擬応答による試験のみ。実際のアプリ登録・認証・書誌検索は未検証。
AniListは2026-10-14に架空検索語による正常な0件応答を確認。実在作品の照合や実運用の制限は未検証。
いずれも利用者が有効にし、候補・採用項目を確認する。未検証の実API動作を正式な相互運用保証に含めない。
キー、実応答、私用の作品補正表は同梱しない。[補完ガイド](METADATA_SOURCES.md) を参照する。
